## DB·권한 / 최종 일괄 배포 대기

`supabase/migrations/202611050001_feed_blocks.sql`은 **아직 운영 미적용**이다. 5단계 전체 검증 및 필요한 운영 변경 승인을 거쳐 마지막 한 번에 적용한다.

- `social_posts.content_blocks`, `post_comments.parent_id`; 신규 `post_poll_votes`, `post_question_answers`, `post_comment_likes`.
- 신규 테이블 RLS ON/직접 권한 회수, 인증된 RPC에서만 접근. caller actor 파라미터를 받지 않고 `auth.uid()`를 사용, 고정 search_path, 익명 RPC 실행권한 없음. 기존 프로필/개인 기록 RLS를 넓히지 않는다.
- v3 저장은 기존 작성자·사진 소유자·본문·일일10개/20초 제한 저장 함수를 같은 트랜잭션에서 재사용한다. 영화 제목/메타는 DB가 authoritative하며 클라이언트 위조 메타를 저장하지 않는다.
- 공개 active 글만 투표/댓글 공감/응답 참여 가능. 투표는 `(post,user)` 유일키와 upsert로 변경하되 중복 인원 증가 방지. 참여가 생긴 투표/질문은 변경·제거 금지. 글은 본인만 수정/휴지통 이동/7일 복원 가능, 복원 시 비공개.
- 질문 응답은 글 작성자를 팔로우한 비작성자만 가능, 한 글당 한 번/하루20개. 응답을 숨겨도 재응답·질문 교체를 허용하지 않는다. 게시자와 응답자 본인에게만 본문 공개. 응답 DTO에 userID/이름/프로필/아바타를 반환하지 않는다. 서비스 운영자는 원본 계정을 식별할 수 있음을 동의 전 안내한다. 기존 신고 기능은 유지하지만 개별 익명 응답 관리자 화면은 이 단계 범위 밖이다.
- 답글은 같은 글의 보이는 루트에만 연결하고 루트를 잠근다. 다른 글·답글의 답글 연결을 거부한다. 본인 댓글만 삭제, 공감 유일키로 중복 방지. 기존 알림 종류를 재사용한다.
- 배포 전 실계정은 capability probe에서 미설치 RPC만 감지해 기존 글/사진/공감/루트 댓글로 후퇴한다. 새 블록을 조용히 버려 저장하거나 가짜 투표 성공을 표시하지 않는다. 네트워크/권한 실패는 우회하지 않는다.
