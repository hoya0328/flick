## 미확인 / 잔여 위험

- Expo/Supabase의 **현재 월 잔여 사용량**, 실제 Google 프로젝트 Free 상태·현재 모델 한도는 계정 대시보드로 새로 확인하지 못했다. 11/05 관측치를 현재 잔여량으로 재사용하지 않는다.
- 최신 배포의 화면 응답 정상은 새 기기에서 가입→게스트/동의→AI→비공개 저장 전체 성공의 증거가 아니다. 실제 QR·휴대폰 네트워크로 개막 전 재확인이 필요하다.
- Supabase Free의 저활동 프로젝트 일시중지 정책과 외부 장애 위험은 남는다. 유입이 있다고 절대 무중단을 보장하지 않는다.
- 공급자 AI 한도는 보장 처리량이 아니다. 한도·장애 시 AI만 제한하고 기록 기능을 유지하는지 운영 개시 전에 재검증한다.
- 이전 UI 게시의 GitHub 의존성 감사35건(34 high/1 moderate, 경로 중복 포함)은 별도 잔여 사항이다. 기존 서비스가 자동 종료되는 원인은 아니며 전체 보안/CI 통과로 표현하지 않는다.

## 운영 개시 전 우선순위와 담당

1. **운영자+개발, P0**: 대시보드의 실제 무료 상태와 월 잔여량, 누적 게스트 수를 확인. 무료 유지 확인 후 사용자 승인 범위에서 전시 종료/AI 확인 기한을 11/24 00:00 KST까지 설정. 익명 로그인·가입 훅과 입장 상태 확인. 기한만 늘리고 무료 요금제를 확인한 것으로 취급하지 않는다.
2. **개발+운영자, P0**: QR 실주소 및 실제 휴대폰에서 신규 게스트→동의→AI(승인 시)→저장, AI 한도/장애 시 수동 기록, 같은 Wi-Fi 입장 검증. 기존 회원의 이메일 가입 조건도 별도 확인.
3. **운영자, P1**: 운영 중 사용량/오류 확인 담당과 연락 수단, 게스트/AI 비상 차단·수동 체험 대체, 기존 beta/롤백 식별자 확보. PC를 계속 켜 두는 것은 서버 가용성 대책이 아니다. 이번 요청으로 반복 자동 점검을 등록하지 않았다.
