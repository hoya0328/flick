# SCREEN STRUCTURE

## 제공된 화면에서 읽힌 구조 의도

화면은 단순한 탭 모음이 아니라 `발견 → 감상 → 기록 → 회고 → 재발견`의 순환을 만들도록 설계되어 있다. 중앙 FLICK 버튼은 이 루프에서 가장 중요한 “빠른 기록 시작” 행동을 항상 노출한다.

`FLICK`는 영화와 손가락 제스처를 뜻하는 Flick와 한 번의 간편한 행동을 뜻하는 Click을 결합한 작업명이다. 포스터 스와이프와 중앙 기록 버튼이 이 브랜드 의도를 행동으로 연결한다.

## 전체 정보 구조

| 영역 | 주요 화면 | 사용 목적 |
|---|---|---|
| 온보딩 | 키워드 선택, AI 질문, 첫 영화 기록 유도 | 취향 데이터 확보와 핵심 가치 체험 |
| 홈 | 주간 Top 10, 키워드 추천, 매거진, 큐레이터 | 탐색 시작점과 콘텐츠 신뢰 형성 |
| 검색 | 개인 추천, 키워드 결과, 영화 상세, 티켓 스캔 | 원하는 작품을 빠르게 찾거나 등록 |
| 기록 | 감상 확인, 가볍게/집중해서 기록, AI 정리, 최종 편집 | 감상을 사용자 언어의 기록으로 전환 |
| 피드 | 게시물, 댓글, 작성 | 기록을 공개 대화로 확장 |
| 프로필 | 캘린더, 내 피드, 보관함, 취향 리포트 | 축적 가치와 재방문 이유 제공 |

## 핵심 화면 흐름

### 첫 사용

스플래시 → 감정 키워드 선택 → AI 개인화 질문 → 첫 기록 또는 탐색 → 개인화 홈

### 영화 발견

홈/검색 → 키워드 추천 목록 → 영화 상세 → 보고 싶어요 또는 기록하기

### 감상 기록

영화 확인·감상일 선택 → 기록 모드 선택

- 가볍게: 별점 → 감정 질문 → 키워드 선택 → AI 정리 → 사용자 수정·완료
- 집중해서: 자유 작성/음성 입력 → 영화 요소별 AI 비평 질문 → 초안 제안 → 사용자 수정·완료

### 기록 활용

완료 기록 → 개인 캘린더·취향 리포트 반영 → 다음 추천 개선 → 선택적 공개

## MVP용 화면 재구성

초기 버전은 탭과 기능을 다음처럼 줄이는 편이 핵심 가설 검증에 유리하다.

- `홈`: 키워드 추천과 최근 기록
- `검색`: 영화 검색·상세
- `기록`: 중앙 주요 행동, 두 기록 모드
- `마이`: 기록 캘린더와 핵심 취향 리포트
- 공개 `피드`는 MVP 이후 별도 탭으로 추가

## UX 원칙

- 기록 시작 전 예상 소요 시간과 질문 수를 보여준다.
- 모든 질문은 건너뛸 수 있고, 중간 저장을 지원한다.
- 키워드는 추천 이유와 기록 결과에서 같은 의미 체계로 사용한다.
- Light와 Core는 서로 다른 사용자가 아니라 상황에 따라 오갈 수 있는 기록 모드로 제공한다.
- AI 결과는 제안으로 표시하고 게시 전 반드시 사용자가 확인한다.
- 공개 범위는 비공개가 기본이며 스포일러 표시를 제공한다.
- 중앙 기록 버튼은 강조하되 일반 탐색을 방해하지 않는다.
- 긴 매거진보다 사용자의 기록과 재방문 정보를 홈 상단에 우선한다.

## 확인이 필요한 화면 결정

- 서비스 공식명이 작업명 `FLICK`으로 확정되는지와 상표 사용 가능성
- 홈의 큐레이터·매거진을 직접 제작할지 외부 콘텐츠로 구성할지
- 기록 완료 후 기본 목적지가 개인 보관함인지 공개 피드인지
- 웹, iOS, Android 중 최초 출시 플랫폼과 로그인 방식
