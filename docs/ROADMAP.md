# ROADMAP

개발은 아래 4단계로 진행한다. 모든 단계는 iPhone 크기를 기준으로 만들고 같은 코드를 반응형 웹에서 함께 확인한다.

## 1단계 - 기반과 온보딩

상태: 완료 (2026-08-07)

범위:

- TypeScript, Expo, Expo Router 프로젝트 생성
- FLICK 디자인 토큰과 공통 컴포넌트
- iOS·웹 공통 탭과 라우팅
- 이메일 OTP와 Apple 로그인 경계
- 스플래시, 감정 키워드 선택, 첫 취향 설정
- Supabase 연결, 프로필과 키워드 저장

완료 기준:

- iPhone 실기기 또는 Expo Go와 반응형 웹에서 동일 계정으로 접속한다.
- 320~480px 화면에서 온보딩을 완료하고 재접속 시 상태가 유지된다.
- 로딩·빈 상태·오류·재시도 화면이 있다.

## 2단계 - 영화 발견

상태: 완료 (2026-08-07)

범위:

- 홈, 검색, 키워드 추천 목록
- 영화 상세, 보고 싶어요, 감상 영화 선택
- TMDB 서버 프록시와 응답 캐시
- 추천 이유와 포스터 출처 표시
- 포스터 스와이프 취향 입력의 최소 실험

완료 기준:

- 검색에서 영화 상세까지 이동하고 보고 싶어요를 저장한다.
- 외부 영화 API가 실패해도 캐시·재시도·안내 상태가 동작한다.
- TMDB 필수 출처 표시가 About/Credits에 노출된다.

## 3단계 - 핵심 기록과 AI

상태: 3A·3B와 3C 질문·태그·Core AI·운영 안전장치 완료 (2026-08-07)

### 3A - 기록 기반 (완료)

- 감상일과 별점 등록
- `나만 보기`/`전체 공개` 저장과 RLS. 초안은 항상 본인 전용
- 0.9초 자동 초안 저장, 기기 복구본, 네트워크 실패 안내
- 기록 목록, 상세 재진입, 수정과 연관 데이터 일괄 삭제

### 3B - Light/Core 기록 (완료)

- Light: 감정 질문, 키워드, 한줄 기록
- Core: 연출·미장센·서사·인물·사운드 질문과 자유 작성
- 두 모드 전환, 스포일러 표시, 완료 전 최소 품질 검증

### 3C - AI 보조와 운영 보호 (완료)

- 완료: 영화 제목·장르·감독·주요 출연진을 이용한 결정적 질문 5개 구성
- 완료: 화면 구성도 기반 한 질문씩 진행, 질문당 최대 3개 느낌 태그, 건너뛰기와 전체 태그 요약
- 완료: 질문·선택지 스냅샷과 사용자 선택 태그의 본인 전용 저장·복구·수정·삭제
- 완료: Core Q1은 영화 메타데이터로 생성하고, A1 이후에는 이전 질문·답변과 영화 정보를 Gemini 서버 함수에 전달해 Q2~Q5를 순차 생성
- 완료: Gemini 오류·무료 할당량 초과·오프라인 시 결정적 안전 질문으로 복구하며 기존 답변은 보존
- 완료: 만 18세 이상 테스트 동의와 개인정보 입력 금지 안내, 키의 Supabase 서버 비밀값 보관
- 완료: Core Q1~Q5에서 키워드 3~5개와 사용자가 수정할 리뷰 초안을 생성하고 자유 감상에 입력
- 완료: 리뷰 초안 별도 동의, 수동 생성, 자동 게시 금지, 기존 자유 감상 교체 확인과 실패 시 입력 보존
- 완료: 질문 하루 20회·분당 6회, 리뷰 초안 하루 5회·분당 2회의 사용자별 서버 한도와 잔여 횟수 안내
- 완료: 개인정보 패턴 사전 차단, Gemini 명시적 안전 필터, 안전 질문 복구와 기존 입력 보존
- 완료: 본문 없는 AI 작업 메타데이터 감사 로그와 30일 보관 정리
- 사용자 최종 승인, 사용량·비용 상한, 실패 시 수동 기록 유지
- 음성 입력은 별도 비용·개인정보 검토 뒤 결정

완료 기준:

- 사용자가 평균 3분 안에 의미 있는 기록을 완료할 수 있다.
- AI가 실패해도 사용자의 입력은 보존되고 AI 없이 완료할 수 있다.
- API 키가 앱 번들·웹 코드·로그에 노출되지 않는다.

## 2.5단계 - 전체 영화 접근과 상세 캐시

상태: 기능 구현 완료, 전체 경량 색인 적재 보류 (2026-08-07)

- TMDB 영화 ID 전체 목록은 경량 색인으로, 출연진·OTT·이미지 등 전체 상세는 사용자가 열 때 서버에서 받아 별도 캐시한다.
- 영화의 내부 UUID는 유지하고 공급자 상세만 갱신하므로 찜과 향후 리뷰·감상 기록은 상세 갱신이나 비활성화로 삭제되지 않는다.
- 2026-08-06 공식 일일 내보내기에서 성인·비디오 제외 1,168,357편을 확인했다.
- 예상 DB 사용량은 약 282MB이며 Free DB 500MB의 절반을 넘는다. 무료 프로젝트를 읽기 전용 상태로 만들 위험이 있어 전체 적재는 비용·용량 승인 전 실행하지 않는다.
- 현재 제공 범위는 빈 경량 색인 스키마, 전체 상세 주문형 수집·캐시, 누락 상태와 강제 재시도, 읽기 전용 용량 감사 도구다.

## 5단계 - 발견과 커뮤니티 확장

디자이너 제안 기능은 화면 배치 순서가 아니라 데이터 의존성 순서로 개발한다. 각 하위 단계는 독립 배포와 사용자 검증이 가능해야 한다.

### 5A - 기존 기반 정리와 공개 콘텐츠 모델

상태: 완료 (2026-08-11)

1. `통합 기록 관리` 완성: Light/Core/초안/완료를 한 화면에서 조회·필터·수정·삭제하고 기존 아카이브 로직을 재사용한다.
2. 공개 Light/Core 기록 조회 계약을 피드용으로 확장한다. 차단·신고·스포일러·페이지네이션·삭제 상태를 먼저 정의한다.
3. 좋아요·댓글·답글·저장 모델, 중복 좋아요 방지, RLS, 관리자 운영 조치와 집계 규칙을 만든다.
4. 노출·상세 이동·반응·저장·새 기록 시작 이벤트를 개인정보 없이 측정한다.

완료 기준: 타 계정 쓰기는 차단되고, 삭제·비공개 전환이 피드와 집계에 즉시 반영되며 핵심 전환 지표를 계산할 수 있다.

완료 내용:

- 통합 기록 관리에서 모든 날짜의 Light/Core, 초안/완료, 나만 보기/전체 공개를 필터하고 이어쓰기·공유·2단계 삭제를 수행한다.
- 공개 완료 기록용 페이지네이션 피드 RPC와 닉네임·영화·반응 집계 계약을 추가했다. 스포일러 본문은 피드 요약에서 숨긴다.
- 좋아요·저장·1단계 답글 댓글·본인 댓글 삭제·중복 방지 신고를 구현하고 기존 공개 기록 상세에 실제 UI를 연결했다.
- 관리자 기록 수정 권한이 켜진 경우 신고를 기각하거나 해당 기록을 비공개로 전환하고 감사 로그를 남긴다.
- 공개 기록 조회, 영화 상세 이동, 공감·저장·댓글·신고·기록 시작을 임의 세션 ID와 허용된 메타데이터만으로 측정한다.

### 5B - 읽고 반응하는 최소 피드

상태: 완료 (2026-08-11)

1. `가볍게 기록 사용자 리뷰`: 공개 Light 기록 카드와 공감·댓글 수를 제공한다.
2. `집중 기록 사용자 매거진`: 공개 Core 기록을 긴 글 읽기에 맞게 제공하고 좋아요·저장을 지원한다.
3. `게시물 상호작용`: 좋아요, 댓글, 답글, 저장을 실제 UI에 연결한다.
4. `사용자 컬렉션`: 사용자가 영화 묶음을 생성·수정·공개·저장한다.

완료 기준: 공개 글 발견→상세 읽기→반응/저장→영화 상세 이동 흐름이 모바일에서 완결된다.

완료 내용:

- 홈에서 Light 리뷰 카드와 Core 매거진을 분리하고 공감·댓글·저장 및 상세 이동을 연결했다.
- 컬렉션을 비공개 기본값으로 생성·수정·삭제하고 전체 공개로 전환할 수 있다.
- 영화 검색과 영화 상세에서 소유한 컬렉션에 영화를 추가하고 상세에서 제외할 수 있다.
- 공개 컬렉션을 다른 사용자가 저장하고 내 컬렉션 화면에서 저장 목록을 다시 찾을 수 있다.
- 내부 테이블 직접 접근은 차단하고 소유자·공개 상태를 검사하는 RPC만 인증 사용자에게 허용한다.

### 5C - 홈 랭킹과 편집형 큐레이션

상태: 완료 (2026-08-11)

1. `실시간 인기 영화 랭킹`: 초 단위가 아닌 최근 7일 기준의 완료 공개 리뷰 수를 주기적으로 집계한다.
2. `최다 선택 키워드 랭킹`: 공개 완료 기록의 키워드를 기간별로 집계한다.
3. 기존 `감정 기반 큐레이션`을 탐색 화면의 명시적 진입점으로 확장한다.
4. `니치 큐레이션`은 관리자 수동 목록으로 먼저 검증하고 이후 AI 보조 여부를 결정한다.
5. `전문가 시점 큐레이션 매거진`은 실제 작성자·출처·게시 권한이 확보된 콘텐츠만 관리자 등록 방식으로 제공한다.

완료 기준: 데이터가 적을 때 빈 랭킹이나 왜곡된 순위를 노출하지 않고, 집계 기간과 추천 이유를 사용자에게 설명한다.

완료 내용:

- 최근 7일 공개 완료 리뷰를 관리자 수동 스냅샷으로 집계하고, 표본 5건 미만에는 영화·키워드 순위를 저장·노출하지 않는다.
- 홈에서 집계 기간·표본 수·마지막 갱신 시점을 설명하며 인기 영화와 최다 선택 키워드를 보여준다.
- 탐색에 감정 선택 진입점을 추가하고 추천 카드마다 선택 감정 또는 장르 기반 이유를 표시한다.
- 니치·전문가 큐레이션의 작성·영화 추가·공개·비공개·삭제를 Super Admin 화면에서 관리한다.
- 전문가는 작성자·HTTP(S) 원문 출처·게시 권한 확인, 모든 큐레이션은 영화 1편 이상을 공개 조건으로 강제한다.
- 큐레이션과 랭킹 원본 테이블 직접 권한을 회수하고 인증·관리자 `security definer` RPC만 허용한다.

### 5D - 취향 리포트와 개인화

상태: 완료 (2026-08-11)

1. `취향 유형 분석`: 설명 가능한 규칙과 최소 기록 수 기준으로 유형을 제시한다.
2. `리뷰 방식별 인사이트`: 기존 Light/Core 비율에서 감정·분위기와 장면·인물·여운 차이로 확장한다.
3. `다시보기 추천`: 과거 별점·키워드·기록 시점과 현재 선택 감정을 결합한다.
4. `필터 버블 방지 큐레이션`: 취향과 다른 작품을 무작위가 아닌 설명 가능한 거리 규칙으로 추천한다.
5. `감상 패턴 분석`: 먼저 키워드·태그의 결정적 누적 분석을 제공하고, 자유 텍스트 AI 분석은 동의·비용·캐시 정책을 확정한 뒤 추가한다.

완료 기준: 데이터가 부족하면 단정적인 유형을 표시하지 않으며, 사용자가 추천·분석 근거를 확인하고 거부할 수 있다.

완료 내용:

- 완료 기록 3편 전에는 `아직 발견 중`으로 표시하고, 이후 선택 태그·키워드·Light/Core 사용량에서 네 가지 감상 신호와 유형 근거를 계산한다.
- 반복 태그·키워드, 별점 4점 이상 다시보기 후보, 현재 취향과 거리가 있는 영화 방향을 모두 설명 가능한 결정 규칙으로 제시한다.
- 리뷰 본문과 AI를 사용하지 않으며 개인화 결과 숨김 상태를 기기에 저장하고 언제든 다시 켤 수 있다.
- 아카이브와 마이 화면에서 `/taste-insights`로 진입하며, 데모에서도 데이터 부족·대조 추천 상태를 확인할 수 있다.

### 5E - 참여형 실험

상태: 완료 (2026-08-11)

1. `히든 블록 리워드 미니게임`: 고정 문제 세트와 서버 정답 판정, 사용자별 해금 상태로 작은 실험부터 시작한다.
2. `인터랙티브 콘텐츠`: 범용 에디터 대신 질문 또는 투표 한 종류의 제한된 블록부터 검증한다.

완료 기준: 보상 조작·중복 응답을 서버에서 막고, 피드·기록 핵심 흐름의 성능과 접근성을 해치지 않는다.

완료 내용:

- 고정 영화 퀴즈 3개를 제공하고 정답은 서버 테이블과 판정 RPC에만 둔다. 사용자별 최대 3회 시도와 정답 시 히든 컬러 블록 해금을 서버에서 강제한다.
- 고정 선택지 주간 투표를 제공하며 사용자·투표 복합 키로 첫 응답만 저장하고 이후 선택 변경을 거부한다.
- 원본 네 테이블의 클라이언트 직접 권한을 회수하고 인증 사용자에게 조회·응답 RPC만 허용한다.
- 홈과 마이 화면에서 `/experiments`로 진입하며 비로그인·데모 사용자는 로그인 안내만 본다.

### 권장 제외·보류

- 사용자 수가 적은 베타에서 초 단위 `실시간` 랭킹을 만들지 않는다. 주기 집계로 시작한다.
- 팔로우·DM·알림 센터는 댓글 운영과 신고 체계가 안정된 뒤 검토한다.
- 전문가 매거진은 콘텐츠 확보와 이용 권한이 확정되기 전 샘플 문구를 운영 콘텐츠처럼 게시하지 않는다.
- 인터랙티브 범용 글쓰기와 자유 텍스트 AI 전수 분석은 비용·안전성 대비 검증 가치가 낮아 마지막에 둔다.
