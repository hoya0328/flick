# ROADMAP

개발은 아래 4단계로 진행한다. 모든 단계는 iPhone 크기를 기준으로 만들고 같은 코드를 반응형 웹에서 함께 확인한다.

## 1단계 - 기반과 온보딩

상태: 완료 (2026-08-07)

범위:

- TypeScript, Expo, Expo Router 프로젝트 생성
- FLICK 디자인 토큰과 공통 컴포넌트
- iOS·웹 공통 탭과 라우팅
- 이메일 OTP와 Apple 로그인 경계
- 스플래시, 감정 키워드 선택, 첫 취향 설정
- Supabase 연결, 프로필과 키워드 저장

완료 기준:

- iPhone 실기기 또는 Expo Go와 반응형 웹에서 동일 계정으로 접속한다.
- 320~480px 화면에서 온보딩을 완료하고 재접속 시 상태가 유지된다.
- 로딩·빈 상태·오류·재시도 화면이 있다.

## 2단계 - 영화 발견

범위:

- 홈, 검색, 키워드 추천 목록
- 영화 상세, 보고 싶어요, 감상 영화 선택
- TMDB 서버 프록시와 응답 캐시
- 추천 이유와 포스터 출처 표시
- 포스터 스와이프 취향 입력의 최소 실험

완료 기준:

- 검색에서 영화 상세까지 이동하고 보고 싶어요를 저장한다.
- 외부 영화 API가 실패해도 캐시·재시도·안내 상태가 동작한다.
- TMDB 필수 출처 표시가 About/Credits에 노출된다.

## 3단계 - 핵심 기록과 AI

범위:

- 감상일과 별점 등록
- Light: 감정 질문, 키워드, 한줄 기록
- Core: 연출·미장센·서사 질문, 자유 작성, 음성 입력 경계
- 서버 전용 AI 비평 가이드와 초안 제안
- 중간 저장, 네트워크 복구, 사용자 최종 승인
- 비공개 기본값과 삭제

완료 기준:

- 사용자가 평균 3분 안에 의미 있는 기록을 완료할 수 있다.
- AI가 실패해도 사용자의 입력은 보존되고 AI 없이 완료할 수 있다.
- API 키가 앱 번들·웹 코드·로그에 노출되지 않는다.

## 4단계 - 아카이브, 리포트와 출시 준비

범위:

- 기록 목록, 캘린더, 상세·수정
- 자주 사용한 키워드, 감정 TOP 3, 별점 분포, Light/Core 요약
- 알림·공유·딥링크의 최소 버전
- 접근성, 성능, 오류 관측, 개인정보 삭제 흐름
- TestFlight iOS 베타 → iOS 출시 점검 → 반응형 웹 공개 → Android 빌드 준비

완료 기준:

- 첫 기록과 두 번째 기록 전환을 측정할 수 있다.
- iOS 베타와 웹에서 핵심 기록 데이터가 일치한다.
- 백업·마이그레이션·롤백 절차가 검증된다.

## MVP 이후

- 공개 피드, 팔로우, 댓글, 좋아요, 스크랩
- 큐레이터·매거진과 미니게임
- 티켓 OCR, 배지·보상, 고급 리포트
- Android 공개 출시는 iOS와 웹 지표를 확인한 뒤 진행
