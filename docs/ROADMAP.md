# ROADMAP

개발은 아래 4단계로 진행한다. 모든 단계는 iPhone 크기를 기준으로 만들고 같은 코드를 반응형 웹에서 함께 확인한다.

## 1단계 - 기반과 온보딩

상태: 완료 (2026-08-07)

범위:

- TypeScript, Expo, Expo Router 프로젝트 생성
- FLICK 디자인 토큰과 공통 컴포넌트
- iOS·웹 공통 탭과 라우팅
- 이메일 OTP와 Apple 로그인 경계
- 스플래시, 감정 키워드 선택, 첫 취향 설정
- Supabase 연결, 프로필과 키워드 저장

완료 기준:

- iPhone 실기기 또는 Expo Go와 반응형 웹에서 동일 계정으로 접속한다.
- 320~480px 화면에서 온보딩을 완료하고 재접속 시 상태가 유지된다.
- 로딩·빈 상태·오류·재시도 화면이 있다.

## 2단계 - 영화 발견

상태: 완료 (2026-08-07)

범위:

- 홈, 검색, 키워드 추천 목록
- 영화 상세, 보고 싶어요, 감상 영화 선택
- TMDB 서버 프록시와 응답 캐시
- 추천 이유와 포스터 출처 표시
- 포스터 스와이프 취향 입력의 최소 실험

완료 기준:

- 검색에서 영화 상세까지 이동하고 보고 싶어요를 저장한다.
- 외부 영화 API가 실패해도 캐시·재시도·안내 상태가 동작한다.
- TMDB 필수 출처 표시가 About/Credits에 노출된다.

## 3단계 - 핵심 기록과 AI

상태: 3A·3B와 3C 질문·태그·Core AI·운영 안전장치 완료 (2026-08-07)

### 3A - 기록 기반 (완료)

- 감상일과 별점 등록
- `나만 보기`/`전체 공개` 저장과 RLS. 초안은 항상 본인 전용
- 0.9초 자동 초안 저장, 기기 복구본, 네트워크 실패 안내
- 기록 목록, 상세 재진입, 수정과 연관 데이터 일괄 삭제

### 3B - Light/Core 기록 (완료)

- Light: 감정 질문, 키워드, 한줄 기록
- Core: 연출·미장센·서사·인물·사운드 질문과 자유 작성
- 두 모드 전환, 스포일러 표시, 완료 전 최소 품질 검증

### 3C - AI 보조와 운영 보호 (완료)

- 완료: 영화 제목·장르·감독·주요 출연진을 이용한 결정적 질문 5개 구성
- 완료: 화면 구성도 기반 한 질문씩 진행, 질문당 최대 3개 느낌 태그, 건너뛰기와 전체 태그 요약
- 완료: 질문·선택지 스냅샷과 사용자 선택 태그의 본인 전용 저장·복구·수정·삭제
- 완료: Core Q1은 영화 메타데이터로 생성하고, A1 이후에는 이전 질문·답변과 영화 정보를 Gemini 서버 함수에 전달해 Q2~Q5를 순차 생성
- 완료: Gemini 오류·무료 할당량 초과·오프라인 시 결정적 안전 질문으로 복구하며 기존 답변은 보존
- 완료: 만 18세 이상 테스트 동의와 개인정보 입력 금지 안내, 키의 Supabase 서버 비밀값 보관
- 완료: Core Q1~Q5에서 키워드 3~5개와 사용자가 수정할 리뷰 초안을 생성하고 자유 감상에 입력
- 완료: 리뷰 초안 별도 동의, 수동 생성, 자동 게시 금지, 기존 자유 감상 교체 확인과 실패 시 입력 보존
- 완료: 질문 하루 20회·분당 6회, 리뷰 초안 하루 5회·분당 2회의 사용자별 서버 한도와 잔여 횟수 안내
- 완료: 개인정보 패턴 사전 차단, Gemini 명시적 안전 필터, 안전 질문 복구와 기존 입력 보존
- 완료: 본문 없는 AI 작업 메타데이터 감사 로그와 30일 보관 정리
- 사용자 최종 승인, 사용량·비용 상한, 실패 시 수동 기록 유지
- 음성 입력은 별도 비용·개인정보 검토 뒤 결정

완료 기준:

- 사용자가 평균 3분 안에 의미 있는 기록을 완료할 수 있다.
- AI가 실패해도 사용자의 입력은 보존되고 AI 없이 완료할 수 있다.
- API 키가 앱 번들·웹 코드·로그에 노출되지 않는다.

## 2.5단계 - 전체 영화 접근과 상세 캐시

상태: 기능 구현 완료, 전체 경량 색인 적재 보류 (2026-08-07)

- TMDB 영화 ID 전체 목록은 경량 색인으로, 출연진·OTT·이미지 등 전체 상세는 사용자가 열 때 서버에서 받아 별도 캐시한다.
- 영화의 내부 UUID는 유지하고 공급자 상세만 갱신하므로 찜과 향후 리뷰·감상 기록은 상세 갱신이나 비활성화로 삭제되지 않는다.
- 2026-08-06 공식 일일 내보내기에서 성인·비디오 제외 1,168,357편을 확인했다.
- 예상 DB 사용량은 약 282MB이며 Free DB 500MB의 절반을 넘는다. 무료 프로젝트를 읽기 전용 상태로 만들 위험이 있어 전체 적재는 비용·용량 승인 전 실행하지 않는다.
- 현재 제공 범위는 빈 경량 색인 스키마, 전체 상세 주문형 수집·캐시, 누락 상태와 강제 재시도, 읽기 전용 용량 감사 도구다.

## 4단계 - 아카이브, 리포트와 출시 준비

상태: 반응형 웹 핵심·운영 함수·외부 beta 완료, TestFlight·출시 점검 보류 (2026-08-10)

범위:

- 기록 목록, 캘린더, 상세·수정
- 자주 사용한 키워드, 감정 TOP 3, 별점 분포, Light/Core 요약
- 알림·공유·딥링크의 최소 버전
- 접근성, 성능, 오류 관측, 개인정보 삭제 흐름
- TestFlight iOS 베타 → iOS 출시 점검 → 반응형 웹 공개 → Android 빌드 준비

완료:

- 완료 기록 월 캘린더, 날짜 선택, Light/Core 필터, 상세·수정 재진입
- 완료 편수·이번 달·평균 별점·감정 TOP 3·별점 분포·Light/Core 리포트
- 두 번째 기록 전환 안내, 초안 이어쓰기 인앱 알림, 명시적 공유·딥링크
- JSON 데이터 내보내기, 비식별 로컬 오류 진단, 이중 확인 계정 삭제 UI
- 반응형 정적 웹 빌드와 출시·백업·롤백 체크리스트

보류:

- 일회용 계정 `delete-account` cascade 삭제 검증
- Apple Developer 계정 기반 TestFlight·iOS 데이터 일치 검증
- 정식 웹 공개 전 약관·개인정보 법률 검토와 운영 모니터링 연결

완료 기준:

- 첫 기록과 두 번째 기록 전환을 측정할 수 있다.
- iOS 베타와 웹에서 핵심 기록 데이터가 일치한다.
- 백업·마이그레이션·롤백 절차가 검증된다.
