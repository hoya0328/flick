# 12가지 영화 취향 — v1

사용자 명세서 v1.0 기준, 2026-10-27. 12유형을 줄이지 않는다. 기존 기록 UI와 데이터는 유지하고 마이페이지 카드 및 기존 취향 상세의 계산/표시만 갱신한다.

## 유형과 입력

`scene` 장면형 · `afterglow` 여운형 · `music` 음악형 · `interpretation` 해석형 · `character` 인물형 · `narrative` 서사형 · `immersion` 몰입형 · `comfort` 위로형 · `aftereffect` 후유증형 · `nostalgia` 회상형 · `everyday` 생활형 · `novelty` 낯선형.

- 완료 기록만 사용한다. 감상일→수정일→ID 역순으로 영화별 최신 Light/최신 Core 각 1개를 선택한다. 별점은 두 방식 중 최신 완료 기록 1개로 정하고 사용자 평균도 고유 영화 기준이다.
- Light: 저장된 질문/태그/질문 버전/직접 선택한 감상 요소/최종 대표 키워드. 기존 감정 키워드 ID는 실제 표시 문구를 통해 변환한다(`nostalgic`은 ‘여운이 긴’이므로 회상형으로 오해하지 않음). 사용자 프로필의 온보딩 선택값만으로 유형을 만들지 않는다.
- Figma Q2는 긍정, Q3는 부정, 분위기/인상/관람 상황 질문은 중립으로 처리한다. ‘어떤 점이 좋았나요?’의 감상 요소는 긍정이다. 구형 질문은 확인 가능한 sourceRule과 선택 문구만 사용한다. 모호한 질문은 중립이며 직접 입력한 미매핑 단어는 임의 해석하지 않는다.
- `taste-taxonomy.ts`에 현재 기본 키워드 전체의 매핑 또는 미분류 결정을 기록한다. 테스트가 Figma 단어/감상 요소/온보딩/구형 장르별 선택지의 누락을 검사한다. 자유 입력의 무한한 동의어를 자동 분류하는 기능은 없다.
- Core: 저장된 질문과 직접 쓴 답변만 분석한다. AI 코멘트·생성 키워드·매거진·영화 줄거리·외부 평론은 제외한다. 문장별 수정 출처는 기존 데이터로 복구할 수 없으므로 편집한 매거진도 분석에서 제외한다. 과거 Core에서 직접 선택한 키워드가 있으면 제한적 규칙 분석에 사용할 수 있다.
- 보고 싶은 영화에는 저장 이유가 없으므로 wishlist 가중치 0. 새 이유 선택 UI나 새 추천 시스템은 만들지 않는다. 기존 다시보기/취향 밖 추천 화면은 보존한다.

## 계산 계약

- 긍정 `1`, 중립 `.3`, 혼합 `.45`, 부정 `-.7`. 유형별 가중치와 곱해 합산하고 영화별 유형 점수는 `[0,1]`로 제한한다. 부정 단독은 선호 점수로 더하지 않으며 원문 분석 결과에는 부정 방향을 보존한다.
- 같은 영화의 같은 단어는 한 번만 센다. 중립+긍정은 긍정 한 번, 긍정+부정 충돌은 혼합 한 번이다. Core의 같은 유형/방향 반복은 가장 강한 근거 하나만 사용해 중복 문장으로 점수를 올리지 않는다.
- 두 방식에 유효 근거가 있으면 Light `.4` + Core `.6`. 없거나 실패한 분석을 0점 벡터로 섞지 않고 분석 가능한 방식만 사용한다. 성공한 빈 AI 결과는 ‘분석했지만 근거 없음’이며 무한 재호출하지 않는다.
- 품질: 정상 Core `1`, 새 Light `.8`, 제한적 구형 입력 `.55`. 최신성 `.8+.2*exp(-ln(2)*ageDays/365)`, 별점 `clamp(1+.05*(영화별점-사용자평균),.9,1.1)`(별점 없으면 1).
- 유형 점수는 가중 평균, 상대 비중은 12점수 합으로 정규화한다. 비중은 검증된 확률/정확도가 아니며 반올림 합이 100과 다를 수 있다.
- 분석 가능한 고유 영화 0~2편/점수합 0은 데이터 부족, 3~7편은 임시. 8편 이상에서 1·2위 차이 6%p 이상 및 1위의 유효 긍정 근거 4편 이상이면 대표 유형, 아니면 상위 두 성향과 기준 미충족을 알린다. 이 기준은 베타 가설이며 검증된 성격 검사가 아니다.
- 미매핑/건너뛰기만 있는 기록은 분석 편수에서 제외한다. 화면에 완료 영화 수와 분석 가능 영화 수를 별도로 표시한다.
- 키워드 TOP5/별점별 표현/별점 분포는 영화별 중복 제거. 포인트 TOP3는 Light의 실제 긍정 감상 요소만 집계하며 Core 원문 언급을 선택 횟수로 둔갑시키지 않는다.

## AI·동의·캐시·보안

- 기존 무료 Gemini 프로젝트 `klick-504806`의 AI Studio 무료 등급을 2026-10-27 재확인했다. `gemini-3.5-flash-lite`만 허용한다. 서버의 `TASTE_FREE_AI_VERIFIED=true` 및 가까운 만료일 `TASTE_FREE_AI_VERIFIED_UNTIL`이 모두 유효해야 호출한다. 이번 확인 기한은 2026-11-03 22:32:51 KST다.
- 유효 기한은 결제 상태를 실시간 보증하는 API가 아니다. 운영자는 이 프로젝트의 Google 결제 등급을 임의로 유료 전환하지 않는다. 변경 시 먼저 무료 플래그를 해제하고 재검토한다. 기한 만료 후 모델/계정 등급을 다시 확인하기 전에는 신규 호출을 차단한다. 기존 키워드 계산과 유효한 저장 분석은 유지한다.
- 원문 분석은 기본 꺼짐. 기록용 기존 AI 동의를 재사용하지 않고 취향 리포트에서 별도 동의를 받는다. 영화 제목·질문·답변이 Google로 전송되며 무료 입력은 서비스 개선에 사용될 수 있음을 안내한다. 명백한 이메일/전화번호/주민번호 패턴은 전송 전에 차단한다(모든 민감정보를 탐지한다는 보장은 아님).
- `analyze-taste-review`는 caller JWT로 본인 완료 Core만 읽고, 타입/강도/방향/질문 키/원문 인용 일치를 검증한다. 질문에만 있거나 원문에 없는 인용은 폐기한다. 인용 일치는 의미 판정의 완전한 정확성을 보장하지 않으므로 사용자에게 베타 결과로 안내한다.
- 기존 Core 질문/초안 한도를 변경하지 않는다. 별도의 DB 직렬화 한도: 계정 5회/UTC일·2회/분, 서비스 전체 30회/UTC일, 같은 리뷰 진행 중 중복 요청 차단. 공급자 무료 한도는 별도여서 더 먼저 429가 날 수 있다. 실패한 실제 시도도 한도를 사용한다.
- 상태/캐시 조회는 AI를 호출하지 않는다. 기존 Core 최초 분석은 동의 후 한 개씩, 동의 이후 새 Core 완료 저장은 비동기로 자동 시도한다. 실패/브라우저 종료는 원본 저장을 막지 않으며 리포트에서 재시도한다. 무제한 자동 재시도·유료 대체 없음.
- `taste_review_analyses`는 사용자 전용. 서버만 쓰며 authenticated의 직접 테이블 읽기/쓰기는 막고 본인 전용 RPC로 유효 캐시만 읽는다. 해시는 저장된 질문+사용자 답변+영화 맥락+추출 버전 기준이며 별점/감상일/AI 매거진은 제외한다. 클라이언트도 현재 답변과 캐시 출처를 대조해 조회 간 경합을 방어한다.
- 원문 수정/질문 변경/비완료 전환은 기존 캐시를 숨긴다. 리뷰 삭제는 FK로 캐시를 제거한다. 별점/매거진만 수정하면 AI를 재호출하지 않고 유형 가중치만 재계산한다. 분석 중 원문·동의가 바뀌면 늦은 응답을 저장하지 않는다.
- 동의 철회는 해당 사용자의 AI 캐시만 삭제한다. 원본 기록과 규칙 기반 리포트는 유지하며 다시 켜도 자동 일괄 분석하지 않는다. 운영 이벤트에는 원문 없이 상태/오류/시간만 기록하고 30일 보존한다.
- 사용자 전체 결과는 순수 계산으로 화면 진입/기록 변경/AI 완료 후 갱신한다. 초기에는 별도 사용자 결과 테이블/유료 큐/예약 작업을 만들지 않는다. 버전 변경은 재계산하며 AI 추출 버전까지 바뀐 경우에만 새 원문 분석이 필요하다.

## 제외 및 롤백
