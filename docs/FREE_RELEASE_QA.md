# 무료 기능 v1 검증·운영 — 2026-10-27

## 제공 범위

| 동선 | 가능한 작업 |
|---|---|
| 마이 → 내 피드 | 일상 글 작성·조회·본인 수정, 7일 휴지통/비공개 복원 |
| 설정 → 공개·알림 설정 | 프로필 공개/비공개, 공개 미리보기, 앱 내 알림, 관리자 별도 신고 권한 |
| 피드 → 플리커 찾기 | 공개 프로필 검색·팔로우, 본인 팔로워·팔로잉 목록 |
| 피드 → 일상 피드/팔로잉 | 공개 글·사진, 공감·댓글·저장·신고 |
| 마이 → 보관함 | 기존 영화/리뷰/매거진/컬렉션 + 저장한 일상 글 |
| 홈/마이 → 알림 | 팔로우·공감·댓글, 개별/전체 읽음, 접근 가능한 원문만 이동 |
| 설정 → 홈 화면에 설치 | PWA 설치 버튼 또는 Safari/Chrome 수동 설치 안내 |

프로필 비공개 전환은 이미 공개한 개별 콘텐츠를 비공개로 바꾸지 않는다. 공개 취소는 각 콘텐츠에서 설정한다. 기존 발급된 사진 서명 URL은 최대60초 후 만료된다. 계정 삭제 외의 글/댓글 삭제는 사진 파일을 자동 삭제하지 않는다.

## 실행 증거

- 서버 마이그레이션 `202610270003_free_community.sql` 적용 전에 동일 DDL+합성 계정 QA를 하나의 트랜잭션에서 실행해 ROLLBACK했다. 리뷰 공감 알림 트리거의 테이블별 필드 참조 오류를 사전 검증에서 수정했다.
- 적용 후 `supabase/tests/free_community.sql` 통과: private 기본값, 본인 CRUD/사진, profiles RLS 유지, 중복/자기 팔로우, 팔로잉 피드, 연속 작성 제한, 공감/저장/댓글, 알림 읽음 계정 격리, 신고 권한/처리/비공개 본문 보호, 7일 복원, moderation 복원 금지, anon 차단, 합성 계정 cascade. 모든 쓰기는 ROLLBACK했다.
- 계정 삭제 함수는 HTTP 모의 테스트로 세션/명시적 확인·본인 폴더 경로·운영 계정 사전 차단·사진 정리 실패·Auth 삭제 실패·timeout의 부분 반영 안내를 검증한다. 실제 사용자 탈퇴나 파일 삭제 요청은 하지 않았다.
- PWA worker를 격리된 JS 환경에서 실행해 cross-origin/API/서명 URL/POST 무시, 개인 화면의 network-only/오프라인 안내, 정적 자산 캐시와 본인 캐시 정리만 검증한다.
- 무료 저장량 읽기 결과: DB 약20MB, 사진4장, 새 공개 프로필0, 새 일상 신고 권한0, 잔여 합성 계정0. 시점별 수치는 사용량이 늘면 달라진다. 유료 결제/업그레이드/다른 서비스 연결은 하지 않았다.
- 최종 type/lint/test, 모바일 및 외부 배포 결과는 `HANDOFF.md` 최신 항목에 기록한다.

## 운영 한도와 관찰

- 글10개/UTC일·20초 간격, 댓글50개/UTC일·분당5개, 본문2,000자/댓글500자, 팔로잉2,000명, 사진 기존 계정16장·전체160장 한도 공유.
- 알림은 앱 내 진입 시 읽으며 메일/OS push/상시 Realtime 구독이 없다. 최근30일 표시 및 조회한 본인 알림의 오래된 행을 정리한다. 휴면 계정 알림의 전역 주기 청소는 예약하지 않았다.
- 일상 삭제 글은7일 후 복원 목록에서 제외하지만 하드 삭제 스케줄은 연결하지 않았다. 서비스 전체 사용량은 Supabase/EAS 기존 대시보드에서 점검하고 한도 접근 시 먼저 신규 기능/업로드를 제한한다. 무료가 영구 무제한이라는 의미가 아니다.
- 기존 Gemini 무료 확인 기한/별도 동의/개인·전체 한도는 유지한다. 이번 기능은 추가 AI 호출을 만들지 않는다. 12유형의 의미 판정 품질은 기존 자동 회귀와 실제 베타 피드백을 구분한다.

## 백업·복원: 무료로 가능한 후속 운영 검증

소스/태그는 사용자 DB·계정·사진 백업이 아니다. 기존 JSON 내보내기도 영화 기록 중심의 사용자 사본이며 전체 서비스 복구용이 아니다. 이번 작업에서 운영 개인정보 전체 dump, 비밀번호 해시 내보내기, 운영 restore는 실행하지 않았다. 논리 백업 자격 증명과 별도 복원 환경이 준비되지 않아 전체 재해 복구는 **미검증**이다.

무료 대안은 운영자가 자신의 PC에 PostgreSQL/호환 CLI를 준비하고, 승인된 DB 연결로 암호화한 논리 백업 및 Storage 원본 사본을 저장한 후 로컬 격리 DB에서 복원하는 방식이다. 새 유료 프로젝트나 자동 업그레이드를 만들 필요는 없다. 단순 파일 무결성 검사와 실제 복원을 구분한다.

1. 프로젝트 ref와 백업 시각을 확인하고 DB/Auth/Storage 각각의 복구 범위·최대 허용 손실 시간을 기록한다. 암호화 저장 위치는 Git/동기화 공개 폴더 밖으로 정하고 키는 분리한다.
2. 공식 CLI/`pg_dump`의 현재 지원 범위와 권한을 확인해 논리 백업을 만든다. public 테이블만으로 Auth 사용자·identities·Storage 바이너리가 복원된다고 가정하지 않는다. 토큰·비밀번호를 채팅/로그에 출력하지 않는다.
3. Storage 사본은 객체 경로·소유 계정·바이트/해시 manifest를 함께 보관한다. DB만 되돌려 서명 URL이나 실제 사진이 살아난다고 판단하지 않는다.
4. **운영 URL로 restore하지 않는다.** 별도 로컬 환경에서 roles/extensions/schema/data 및 필요한 Auth 매핑을 복원하고 원본 수·관계·사진 해시·계정 격리를 비교한다. 외부 메일·Gemini·webhook은 차단한다.
5. 복구 성공 시 대상·소요 시간·손실 범위·검증 결과만 저장하고 암호화 원본은 별도 보관한다. 이 리허설 전에는 ‘복구 검증 완료’로 표시하지 않는다.

## 미실행/수용 위험

- 의존성 점검에서 호환 전이 패키지9개를 갱신해 기존 critical `shell-quote`와 여러 high 경고를 제거했다. Expo57/Router57/RN0.86은 유지했다. `npm audit --omit=dev`에는10개(경고 경로 포함: high4/moderate6)가 남는다. `image-size`의 이미지 파서와 `zod`는 Metro/Expo CLI 도구 경로, `uuid`는 xcode v4 생성 경로다. 외부 beta는 Node 개발 서버가 아닌 정적 웹이므로 해당 빌드 도구를 외부 요청으로 실행하지 않는다. `decode-uri-component`의 query-string 경로는 URL 처리 런타임에 남는 moderate DoS 위험이다. `audit fix --force`는 Expo 메이저 변경을 제안해 실행하지 않았다. SDK/파서 호환 업그레이드는 별도 범위에서 처리하며 ‘취약점0’ 또는 정식 출시 보안 완료로 판단하지 않는다.

- iPhone/Android 실기기 홈 화면 설치, 앱 전환/브라우저별 음성팩 지원, 실제 일반 계정의 사진 포함 최종 탈퇴 E2E는 사용자 또는 별도 일회용 계정으로 후속 검증한다. 사용자 실계정 삭제로 QA하지 않는다.
- Storage 정리와 Auth 삭제는 원자적이지 않다. 실패하면 일부 사진이 먼저 삭제될 수 있으며 UI가 이를 명시한다. 관리자/감사 기록/편집 콘텐츠 소유 계정은 자동 탈퇴하지 않고 운영 이관 절차를 거친다.
- 블록/뮤트/DM/외부 푸시, 유료 SMTP, 전체 백업 자동화, 전문가 콘텐츠 권리 확보, 유료 모델 확대는 이번 기능 범위가 아니다.
- 롤백은 Git 태그와 직전 EAS deployment를 사용해 코드/웹만 되돌린다. 추가 테이블·사용자 콘텐츠를 drop하지 않는다. 새 테이블은 RPC-only이므로 구버전 클라이언트와 공존한다. PWA 새 버전은 열린 작성 화면을 강제 재시작하지 않는다.
