# TMDB 전체 영화 접근 설계

## 데이터 분리

- `movies`: FLICK 내부의 안정적인 영화 UUID와 검색·목록용 요약
- `movie_details`: 출연진, 제작, 이미지, 영상, 번역, 개봉 정보, 한국 OTT 등 TMDB 전체 상세 캐시
- `tmdb_catalog`: 공식 일일 ID 내보내기로 만들 수 있는 전체 경량 색인. 현재는 빈 상태
- `watchlist`와 향후 리뷰·감상 기록: `movies.id`를 참조하므로 상세 캐시 교체나 TMDB 비활성화와 독립적으로 유지

## 동작

1. 검색·추천으로 받은 영화 요약을 `movies`에 캐시한다.
2. 사용자가 상세 화면을 열면 Edge Function이 TMDB 상세와 부속 정보를 한 번에 요청한다.
3. 응답을 `movie_details`에 저장하고 만료 전에는 캐시를 사용한다.
4. 누락은 `source_incomplete`, 호출 실패는 `failed`로 구분하며 사용자가 강제로 다시 확인할 수 있다.
5. TMDB에서 사라진 작품은 삭제하지 않고 비활성화해 사용자 데이터의 참조를 보존한다.

## 비용 안전선

`npm.cmd run catalog:audit`는 TMDB 공식 일일 내보내기를 읽기만 하며 DB에 쓰지 않는다. 2026-08-06 자료는 성인·비디오 제외 1,168,357편, 기본 인덱스 포함 예상 약 282MB였다. Supabase Free DB 500MB를 보호하기 위해 전체 적재는 실행하지 않는다. 전체 검색이 필요해지면 유료 DB 전환, 외부 검색 인덱스, 또는 범위 분할 중 하나를 먼저 결정한다.
