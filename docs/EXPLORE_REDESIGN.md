# 탐색 · 영화 목록 · 상세 (Figma 5단계 중 2단계)

기준 파일 `7o0aA5nN2muGSgSEdtsYw7`, 구역 `26:776`. 화면은 탐색 `26:1316`(402×2389), 목록 `26:1044`(402×1757), 상세 `26:777`(402×2176), 취향 밖 공개 전 상태 `26:1581`이다. 코드 문맥과 원본 이미지를 대조하며 기존 Expo/Router/Supabase를 유지했다. OS 시각/배터리/홈 바는 웹에 그리지 않는다.

## 구현과 진입

- `/search`: 새 탐색 허브, 검색 입력, 기기별 추천 비율, 상황별 카드, 키워드 추천, 탭하여 공개하는 취향 밖 영화/후보 선택, 니치 큐레이션, 공개 컬렉션.
- `/explore-list`: 키워드·상황·니치별 목록, 검색, 장르/평점/추천·최신·평점 정렬, 필터 적용/초기화, 로딩·오류 재시도·빈 상태. 키워드/필터는 URL에 남아 새로고침/뒤로에서 복원된다. 비로그인은 로그인 안내로 이동한다.
- 기존 `/search?query=` 링크는 새 목록으로 연결한다. URL 텍스트는 최대120자만 사용하고 새 외부 redirect를 받지 않는다.
- `/movie/[id]`: 포스터 배경/상단 이동·저장·공유, 실제 메타데이터와5점 환산 평점, 기록 선택 하단 시트, 보고 싶어요, 추천 이유, 키워드/소개/가이드, 공개 Light·Core 카드, 연관 영화, 내 컬렉션 담기. 감독/출연/제작사/한국 OTT·출처·상세 새로고침은 상세 정보 창에 보존한다.
- 공개 리뷰 카드의 공감/댓글 수는 읽기 요약이다. 실제 공감/댓글 작성은 해당 기록 상세에서 한다. 스포일러 본문·대표 키워드는 감춘다. 사용자 표지 사진은 기존 private Storage 접근 컴포넌트로 읽는다.

## 무료 추천 계약

- 새로운 AI/벡터 DB/검색 유료 서비스를 연결하지 않는다. 기존 서버의 광범위 후보와 선택 취향/제목 검색 후보를 최대2회 호출해 합친다. 현재 서버가 반환한 후보 안에서만 정렬하며 TMDB 전체를 가져왔다고 표시하지 않는다. 데모는 외부 탐색 API 없이 기존 로컬8편을 사용한다.
- ‘낯선 영화’는 현재 취향 ID와 겹치지 않는 후보다. 슬라이더0~100%(10% 단위)는 이 후보가 섞이는 **목표 비율**이며 매칭 확률/추천 신뢰도가 아니다. 후보 부족 시 다른 쪽으로 채우고 실제 비율 차이를 안내한다. 최근 완료 기록의 영화별 최신 한 건을 최대30편 사용하며 초안/중복 영화는 제외한다. 신호가 부족하면 최초 취향을 사용한다.
- 키워드·기분 검색은 승인된 키워드 별칭과 저장된 제목/원제/소개/장르 단어 일치다. 장면의 의미를 이해하는 AI 검색은 아니다. 장르 필터와 SF/판타지 칩은 실제 장르를 사용한다.
- 취향 밖 카드는 키워드 비중복·TMDB7.5/10 이상인 현재 후보에서 고른다. 평가 인원·타인의 선호 근거가 없는 경우 만들지 않는다. 후보가 없으면 안내한다. 상황/니치 카드는 키워드 규칙으로 추천하며 모든 작품의 대사량이나 만족도를 보장하지 않는다. 실제 게시된 니치 큐레이션이 있으면 우선 연결한다.
- TMDB 점수는 `/2`한5점 값이며 사용자 평점과 구별한다. 평가 인원/국가/관람 등급이 없는 경우 Figma 예시 수치를 복사하지 않는다. 감상 포인트는 장르·키워드 기반 관람 제안이며 작품의 사실/AI 분석을 생성하지 않는다.

## 데이터·권한

- DB/schema/RLS/RPC/AI 함수와 운영 권한을 바꾸거나 배포하지 않았다. 기존 보고 싶어요는 본인 계정에서만, 컬렉션은 기존 소유자/RPC 계약으로 저장한다. 실제 계정에서 예시 UUID를 실영화와 섞지 않고 예시 영화 저장을 차단한다.
- 계정 식별자가 바뀌면 이전 사용자의 취향 신호와 보고 싶어요 상태를 렌더링하지 않으며 이전 비동기 결과는 무시한다. 소개/기존 기록·계정 데이터는 삭제하지 않는다.
- 영화별 공개 감상은 기존 `list_public_reviews`의 최신 공개 완료 기록 **최대50개 중 영화 일치분**이다. 전체 영화별 리뷰 수로 표시하지 않으며 더보기에도 조회 범위를 명시한다. 전용 영화별 전체 조회가 필요하면 별도 RPC/페이지네이션을 설계·검증 후 운영 승인 절차로 추가한다.
- 빈 컬렉션/실제 계정 없는 데모에 디자인 예시 작성자/관계 수/리뷰를 실데이터처럼 생성하지 않는다. 실사용자 프로필 사진이 응답에 없으면 이니셜을 표시한다. 한국 OTT 목록은 제공처 확인이 필요하다.

## 자산과 검증

- 원본 SVG18개와 상황 사진3개는 `assets/figma-explore/README.md`. 기존 벡터 렌더러·HomeRail·폰트를 재사용하고 슬라이더는 키보드/터치/보조기술이 동작하는 코드 기반 벡터 컨트롤로 구현했다. 영화/사용자 콘텐츠 이미지는 동적 데이터를 유지한다.
- `npm run design:check`가 소개7개/탐색18개 SVG의 원본 XML·intrinsic 크기/manifest 일치를 검사하며 check/build에도 연결된다.
- 최종 실행 결과·브라우저 증거·검증 한계는 `HANDOFF.md`의 최신2단계 항목을 따른다. 운영 실계정 저장/공감·실제 OTT 최신성·실기기/native 바이너리·전체 보안 회귀를 이번 데모 UI 검증과 혼동하지 않는다.
- 5단계 전체와 최종 회귀·보안 검증 완료 전 commit/push/tag/beta 배포는 금지한다.
